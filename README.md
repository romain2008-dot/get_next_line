# get_next_line

*This project has been created as part of the 42 curriculum by romgutie.*


## Description

**get_next_line** is a C function that reads a file descriptor and returns its content **one line at a time**, including the terminating newline character (`\n`) when present.

The goal of this project is to deepen the understanding of:
- File descriptors
- Static variables
- Memory management
- Buffered reading using `read()`

The function must be able to handle:
- Arbitrary line lengths
- Any valid file descriptor
- Repeated calls without losing previously read data

## Instructions

### Compilation

The project does not produce an executable by itself.  
You must compile `get_next_line.c`, `get_next_line_utils.c`, and their header alongside your own files.

Example:

```
cc -Wall -Wextra -Werror -D BUFFER_SIZE=42 get_next_line.c get_next_line_utils.c main.c
```

### Usage
Prototype:

```
int fd = open("file.txt", O_RDONLY);
char *line;

while ((line = get_next_line(fd)))
{
	printf("%s", line);
	free(line);
}
close(fd);
```

Each call returns:
- The next line read from `fd`
- `NULL` when there is nothing left to read or on error

## Algorithm explanation

### General strategy

The implementation in based on a static buffer (stash) that stores unread data between function calls.

The algorithm follows four main steps:
1. Read from the file descriptor
2. Accumulate data in stash
3. Extract one complete line
4. Preserve remaining data for the next call

### Step 1 — Buffered Reading

- Data is read using `read()` in chunks of size `BUFFER_SIZE`
- Each chunk is appended to the existing stash using `ft_strjoin`
- Reading stops as soon as a newline (`\n`) is found or EOF is reached

This avoids unnecessary reads and improves efficiency.

### Step 2 — Line Extraction

- The function scans the stash until it finds `\n` or the end of the string
- A substring is extracted from index `0` up to (and including) `\n`
- This substring is returned as the next line

### Step 3 — Cleaning the Stash

- After extracting a line, the consumed part is removed
- The remaining content (if any) is stored in a new stash
- If no data remains, the stash is freed and set to `NULL`

### Step 4 — Static Persistence

- The stash is declared `static` inside `get_next_line`
- This allows data to persist across multiple calls without using global variables

### Error Handling

- Any `read()` error immediately frees allocated memory and returns `NULL`
- All allocations are checked to prevent undefined behavior
- Memory is freed as soon as it is no longer needed

### Why This Algorithm

This approach is:

- Compliant with the project constraints
- Memory-efficient
- Scalable for large files and small buffer sizes
- Simple to reason about and debug

It cleanly separates responsibilities:

- Reading
- Line extraction
- State preservation
